# Architecture

What exists in the code and data. It describes; it does not decide. The method
is in AGENTS.md and the working plan; the claim and coding records below
are the DEPENDENCE pilot's, not the current design.

The site and the dataset share one set of files. The site reads them, and the
Hugging Face release publishes them. Nothing in `data/` is site-specific.

## The chain

```
work → passage → claim → question → draw → coding
```

| Record | What it is | File | Status |
|---|---|---|---|
| Work | A published text: author, title, year, language, form, text status, English translation status, Wikidata ID | `data/works.json` | 206, selections approved 29 Sep 2026 |
| Theme | A group of questions | `data/themes.json` | 16, draft 0.1 |
| Question | A candidate question for the benchmark | `data/questions.json` | 40 candidates |
| Stance | One work's answer to one question: side, argument, location, how it was checked | `data/stances.json` | 275, unverified |
| Passage | An excerpt of a work, with a machine translation if not in English | `data/passages.json` | 11 (Spengler, Berdyaev), unchecked |
| Claim | One row of a theme's position key: verdict, reason, source passage | `data/trials/<theme>.json` | DEPENDENCE drafted (superseded) |
| Model | A respondent: historical, modern base, or deployed | `data/models.json` | 6 entries |
| Draw | One verbatim model response, never edited | `trial/runs/*.jsonl` | DEPENDENCE pilot |
| Coding | Judge output for one draw: which claim it commits to, valence, committing sentence | `trial/judge/` | DEPENDENCE pilot |

`questions`, `works`, `stances` and `passages` are generated by
`scripts/build_data.py` from `research/canon-candidates/`, the canon download
manifest (`trial/corpus/canon/manifest.json`) and `research/translations/`.
Edit the sources and rerun the script; do not edit the generated files. The
earlier 89-work seed list is kept at `data/archive/seed-works-v0.1.json` for
the pilot results pages. The 100-question bank from the prototype survives on
the `prototype` branch as a pilot record.

## Theme fields

`themes.json` stores, per theme: slug, name, question, summary and `direction`
(`machine`, `human`, `both`). Direction is Claude's proposed tag, not decided
(AGENTS.md, Open). A theme's works are derived from its questions' stances.

## Identifiers

- Work IDs are `author-shorttitle` slugs and never change once published.
- Every work and author gets a Wikidata QID where one exists. A missing ID is
  `null`, never a guess. Work IDs point to the work, not to one edition.
- Theme slugs are URLs: `/themes/<slug>`.
- Every data file has `version` and `date` fields. A result is always reported
  against a named version of the position key.

## Work status

`seed` means the work was proposed but has not been checked against an
edition. `verified` means a historian has checked the author, title, date, and
the relevant pages.

## Routes

| Route | Content |
|---|---|
| `/` | Index: one row per question, grouped under its theme; rows expand to the works on each side. Or theme cards (`?view=cards&sort=earliest`) |
| `/themes/[slug]` | One theme: its questions with each side's works, then all its works |
| `/themes/[slug]/results` | Pilot results: one meter of 20 squares per condition per claim, grouped by outcome. How each model answered (generated summary + unprompted squares), then argument by argument for one model (`?model=`). DEPENDENCE only |
| `/themes/[slug]/results/[response]` | One model answer verbatim, with its prompt, codes, and a map of every answer |
| `/questions/[slug]` (`/questions` redirects to `/`) | One question: sides with arguments, passages, link to search |
| `/sources` | All works; filters (`?lang=&form=&century=&text=`) and sort (`?sort=`) |
| `/sources/[id]` | One work: record, its answer to each question, passages |
| `/keys` | Position keys for the six pilot questions: sign-in, then each historian's progress per question. Not in the nav |
| `/keys/[q]` | One question's pool of passages (`research/keys/pools.json`). The signed-in historian sorts them into at most 15 positions (implied answer, argument, Yes/No/Other), one place per passage. Locks when Ben and Nathan have both finished |
| `/keys/[q]/agreement` | Opens when both have finished: agreement for each pair of Ben, Nathan and Claude (`research/keys/claude.json`), each passage's place in the three lists, and the three lists. `/keys/[q]/compare` redirects here |
| `/keys/[q]/final` | The final list, edited by Ben and Nathan together; freezes when both agree to the same version (`research/keys/PROCEDURE.md`) |
| `/coding` | Redirects to `/keys`. The 60-item passage check it held is retired |
| `/search` | Semantic search. Locally over every corpus in `trial/corpus/index/` (1.8 GB, not deployed); deployed over the canon only, from `search-index/` (written by `build_index.py --deploy`). Needs `OPENAI_API_KEY` to embed queries |
| `/models` | Respondents grouped by role (`role` in `data/models.json`): core comparison, context, candidates |
| `/method` | Plain summary of the working plan and the 13 Oct 2026 decisions. Keep in step with `docs/proposals/2026-09-28-benchmark-method.md` |
| `/about` | The premise, pilot status, authors, funding, repository |

Claude's stances for the six pilot questions are hidden from public pages
while their keys are built (`src/lib/data.ts`). Sortings and final lists
are saved to `research/keys/entries/` when run locally, or to
Upstash Redis (keys `keys:ben`, `keys:nathan`, `keys:final`) when `KV_REST_API_URL`/`KV_REST_API_TOKEN`
are set. Passcodes come from `CODING_PASSCODE_BEN` and
`CODING_PASSCODE_NATHAN` (not needed locally).

View, sort, model and search parameters live in the URL and are rendered on
the server, so pages can be linked. List rows expand with native `<details>`.
Client components: the header's active link, the wordmark's hover effect, the
typeface toggle, and the hover card on answer squares.

## Models

`data/models.json` lists respondents with a status (`planned`, `piloted`).
Local runs use Hugging Face weights: Talkie with PyTorch on the Mac GPU
(`trial/run_talkie.py`), Qwen with MLX (`trial/run_qwen.py`). Deployed models
would run through OpenRouter, which does not serve base models.

## Release

The Hugging Face dataset will contain `works`, `themes`, `passages`,
`positions`, `questions`, and the raw and coded runs, plus a datasheet. Full
texts are included only where they are in the public domain.

## Code layout

```
data/             dataset (JSON), the single source of truth
src/lib/data.ts   types, loaders, sorting, formatting
src/components/   ThemeIndex, WorksTable, Meter, ResponseHover, Wordmark, FaceToggle, …
src/lib/          data.ts (themes, works), trials.ts (pilot results), search.ts (local search)
src/app/          routes
trial/            DEPENDENCE pilot: prompts, runners, judging, corpora (large files git-ignored)
bench/            reckoning pilot (July 2026), superseded
research/         pilot records from the prototype
docs/             this file, design.md, pilots.md, proposals/
```
